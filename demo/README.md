# Demo assets

Sample inputs for exercising PlanAround's AI extraction paths without using real, private student material.

## `sample-assignment.txt`

A synthetic assignment brief for the "paste text" and "assignment AI analysis" flows. It includes a title, a deadline, a module weighting, and several rubric tasks with marks, so extraction can be checked end to end (title, deadline, weight, tasks, marks, complexity).

It is not tuned to exploit parser/model edge cases; it represents a plausible student brief.

## Sample timetable

The existing sample timetable PDF lives at [`public/semester-1-timetable.pdf`](../public/semester-1-timetable.pdf) and is generated by [`scripts/create_demo_timetable.py`](../scripts/create_demo_timetable.py). Use it for the onboarding/timetable-import step of a demo. It has a readable text layer, so the deterministic parser handles it directly.

## PDF upload fixtures

These exercise the client-side PDF routing added for assignment briefs and timetables (`lib/pdfDocument.ts`): extract embedded text first, and only render a PDF to an image for visual analysis when there's no usable text layer or the deterministic timetable parser can't read it.

- [`software_engineering_project.pdf`](software_engineering_project.pdf) - a normal, text-layer assignment brief PDF. Text is extracted locally and goes through the existing text-analysis path.
- [`cloud_distributed_systems_scanned.pdf`](cloud_distributed_systems_scanned.pdf) - an image-only assignment PDF (no text layer) built from `02_cloud_distributed_systems_full.png`. Extraction finds nothing useful, so the page is rendered locally and analysed through the existing image path.
- [`demo_timetable_visual_grid.pdf`](demo_timetable_visual_grid.pdf) - a timetable PDF with a compressed content stream the deterministic parser can't read. It falls back to a client-side render and visual timetable analysis.
